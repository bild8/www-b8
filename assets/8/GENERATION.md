# 8 Asset Generation

## Executable Build

Run from the repository root using Node.js `24.19.0`:

```sh
npm ci --ignore-scripts
npm run build
npm run check
npm test
```

The lockfile pins `@resvg/resvg-js` and the PNG encoder. The unmodified static
Hanken Grotesk Black TTF and its OFL license are vendored in `fonts/`, with
upstream commit and hashes in `fonts/source.json`. Builds require no network
after installation and explicitly disable system-font discovery.

`scripts/generate.mjs` uses `brands.json` for brand identity and the geometry in
`icon-spec.v1.json`. Validation rejects duplicate or missing IDs, incomplete
artifact records, path/size mismatches, and inconsistent brand/layout data.
`npm run check` rebuilds in memory and compares all generated bytes, including
checksums and previews. It never rewrites stale output to make a check pass.
Original reference files remain immutable inputs and retain their old hashes.
Update the specification's `generatedAt` date when intentionally changing the
font, geometry or catalog; ordinary rebuilds never insert the current time.

SVGs embed the complete TTF as a data URL and include its license in metadata.
Glyphs remain `<text>` as required. This makes SVGs larger; it avoids reliance
on an installed font. For renderers that ignore embedded fonts, use a generated
PNG. The native build renderer receives the same TTF explicitly.

The November 2026 rebuild uses the actual pinned Hanken Grotesk face; some
glyphs differ from the earlier outputs produced without a checked-in renderer.
The existing geometry and primary brand colors are retained. This catalog is
a consistent Hanken-based interpretation, not a pixel-identical reconstruction
of the uploaded reference logos.

Microsoft variants are generated separately; their hashes are stored in
`microsoft/manifest.json`. See [MICROSOFT-INTEGRATION.md](MICROSOFT-INTEGRATION.md).

The canonical prompt for these icons is machine-readable:

- [icon-spec.v1.json](icon-spec.v1.json) describes the icon geometry, font
  rules, output dimensions, file paths, and SHA-256 checksums for every icon and
  every generated resolution.
- [icon-spec.schema.json](icon-spec.schema.json) defines the JSON shape.
- [VISUAL-CONTROL.md](VISUAL-CONTROL.md) embeds the current SVG and PNG outputs
  for visual review.

The text below is only a human-readable summary of the machine prompt.

## Current Geometry

The current SVGs use a `192 x 192` viewBox.

- Background: `<rect x="1" y="1" width="190" height="190" rx="18" ry="18">`
- Left horizontal line: `M0 76 H94`
- Vertical/curve divider: `M94 160 C94 115 94 82 94 76 C94 54 101 31 124 25`
- Right horizontal line: `M143 76 H166`
- Large `8` shadow: `x=134.5`, `y=126`, `font-size=98`, `font-weight=900`,
  `opacity=0.70`, transform `translate(134.5 87) scale(0.92 1.18) translate(-134.5 -87)`
- Large `8` foreground: `x=126.5`, `y=121`, `font-size=98`,
  `font-weight=900`, transform `translate(126.5 84) scale(0.92 1.18) translate(-126.5 -84)`
- Small letter shadow: foreground `x + 7`, foreground `y + 5`,
  `opacity=0.70`

## Verification Checklist

Before publishing regenerated assets:

- All SVGs contain `Hanken Grotesk`.
- Catalog and Microsoft SVGs embed the exact font from `fonts/source.json`.
- No SVG contains `Roboto`, `Arial Rounded`, `opentype`, or vectorized glyph
  path markers from old font conversion.
- The line paths are split as `M0 76 H94` and `M143 76 H166`.
- `preview_a-z8_colored.png` is `1540 x 880`.
- PNG folders render at `32 x 32`, `192 x 192`, and `526 x 526`.
- Compare `o8`, `p8`, `s8`, and `f8` against their reference PNGs:
  the small letters start below the horizontal line, and the `8` does not show
  the divider line through its counters.
